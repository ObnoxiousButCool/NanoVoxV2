# Migrations

Alembic is wired up from the first commit (D7) so no schema change is ever applied
by hand. The database URL comes from the application settings, not from
`alembic.ini`.

There are no revisions yet: **P0 introduces no tables.** The first revision arrives
with the first mapped entity in P1.

Run from `Code/Backend` with the virtual environment active:

```bash
alembic revision --autogenerate -m "add call and transcript tables"
```

```bash
alembic upgrade head
```

```bash
alembic downgrade -1
```

Every autogenerated revision is reviewed before it is committed — autogenerate
proposes, it does not decide. `render_as_batch` is enabled because SQLite cannot
alter columns in place.
